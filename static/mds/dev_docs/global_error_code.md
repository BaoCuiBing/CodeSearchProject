# 全局错误码文档

## 文档说明
本文档定义了CodeSearchProject项目中所有API接口使用的统一错误码规范，适用于APP端和管理端所有接口。

## 错误码规范

### 成功状态码
| 错误码 | 说明 | 使用场景 |
|--------|------|----------|
| 200 | 请求成功 | 所有正常成功的请求 |

### 客户端错误码
| 错误码 | 说明 | 使用场景 |
|--------|------|----------|
| 400 | 请求参数错误 | 参数缺失、格式错误、验证失败 |
| 403 | 权限不足 | 无权操作、无权访问 |
| 404 | 资源不存在 | 请求的资源未找到 |
| 409 | 资源冲突 | 重复提交、数据冲突 |

### 服务器错误码
| 错误码 | 说明 | 使用场景 |
|--------|------|----------|
| 500 | 服务器内部错误 | 系统异常、未知错误 |
| 502 | 网关错误 | 上游服务异常 |
| 503 | 服务不可用 | 系统维护、过载 |

## 响应格式标准

### 成功响应格式
```json
{
    "code": 200,
    "msg": "操作成功",
    "data": {
        // 具体数据
    }
}
```

### 失败响应格式
```json
{
    "code": 400,
    "msg": "错误信息"
}
```

## 错误处理建议

### 前端处理
1. 403错误：显示权限不足提示
2. 404错误：显示资源不存在提示
3. 400错误：显示具体错误信息，引导用户修正
4. 500错误：显示系统繁忙提示，建议稍后重试

### 后端处理
1. 所有异常必须捕获并返回统一格式的错误响应
2. 敏感信息不得暴露在错误信息中
3. 详细错误信息应记录在服务器日志中
4. 业务验证失败应返回400及具体错误原因
5. 权限不足应返回403

## 扩展说明
如需新增错误码，请遵循以下原则：
1. 优先使用标准HTTP状态码
2. 业务错误优先使用400，配合具体错误信息
3. 避免使用非标准状态码
4. 错误信息应清晰明确，便于前端展示和用户理解

Skills 简介

Skills 是一个开放格式，用于为 AI 代理添加专业技能和知识。

通过 Skills，你可以将特定领域的专业知识、工作流程和最佳实践封装成可重用的技能包，让 AI 代理在需要时自动调用。

在学习 Skills 之前，我们先搞清楚一个更基础的问题：什么是 AI 智能体？

大家肯定用过 ChatGPT、豆包、通义千问这类工具吧？你打字问它问题，它给你文字回答。这就是我们常说的大模型聊天机器人。

ChatGPT、豆包、通义千问这类工具很聪明，但它们有一个致命的问题：它只能说，不能做。

你问它：今天北京天气怎么样，它只能根据训练时学过的知识猜一个答案，而不是真的去看一眼天气。

智能体 = 一个能听懂你的话、能自己思考、还能动手干活的 AI 助手。

聊天机器人是嘴替，智能体是真正的手替。

那智能体是什么？

智能体 = 大模型 + 能动手做事的能力。

还是刚才的例子：

聊天机器人 智能体
你问：今天北京天气怎么样？ 北京今天大概晴天，气温约25度（猜的） 真的去调用天气接口，告诉你: 今天北京多云，23°C，湿度45%"（真实的）
你问：帮我查一下上个月的销售额 抱歉，我无法访问你的数据库 真的去数据库里查，把数据拉出来给你看
你说：帮我订一张明天去上海的高铁票 你可以去12306网站订票 真的帮你打开12306，查票、选座、下单

区别就一句话：聊天机器人是嘴上说说，智能体是真的去干。

智能体是怎么做到的？

一个智能体大概有这么几个部分组成：

三步走：

  1. 听懂你要什么（靠大模型）
  2. 决定用哪个技能去做（靠大模型）
  3. 执行技能，把结果给你（靠 Skills）

你现在生活中已经能见到的智能体

其实很多产品已经在用智能体了：

  • Siri / 小爱同学 / 天猫精灵 — 你说"定个闹钟"，它真的帮你定，不是告诉你"你可以自己定"
  • GitHub Copilot — 不只是聊天，它真的能帮你写代码、改代码
  • 各种AI客服 — 不只是回答问题，还能帮你查订单、退款、改地址
  • 自动驾驶 — 也是一种智能体，它能感知环境、做决策、执行操作

智能体的 Skills 是什么？

智能体的大模型 = 大脑（负责理解、决策、说话）
Skills = 手和脚（负责动手干活）

没有 Skills 的智能体，就像一个只有大脑没有手脚的人——什么都懂，但什么都做不了。

智能体本身很聪明，但它需要有人告诉它——在这个具体环境里，完成这个具体任务，应该用哪些工具、走哪些步骤、注意哪些坑。

这份说明书，就叫做 Skill。

用更贴近生活的比喻理解 Skills:

把智能体想象成一位聪明的新员工，他能力很强，但第一天来公司什么流程都不懂。
Skill 就是公司的 SOP 手册（标准操作流程）。
有了这本手册，他就知道：遇到客户投诉该怎么处理、出差报销流程是什么、代码提交要走哪些审核……不需要每次都问你，能自己完成任务。

Skills 在技术上是一个 Markdown 文件（SKILL.md），写着该任务的完整执行指南。它由人类编写，然后被智能体在执行任务时自动读取和遵循。

Skills 能解决什么问题？

场景一：没有 Skills 时

假设你叫 Claude 帮你 生成一份 Word 文档：

你：帮我生成一个项目计划书的 Word 文档

Claude：好的，以下是项目计划书内容：
（输出一堆 Markdown 文本……）

结果：Claude 输出的是纯文字，不是真正的 .docx 文件。因为它不知道你的环境里有哪些库、文件应该放哪里、格式要求是什么。

场景二：有了 Skills 之后

当系统配备了 docx Skill 后，Claude 在接到同样的请求时，会：

  1. 自动识别"这是 Word 文档任务" → 触发 docx Skill
  2. 读取 Skill 文件，了解正确的库（python-docx）和输出路径（/mnt/user-data/outputs/）
  3. 按照 Skill 的步骤，生成真正的 .docx 文件
  4. 把文件交给你下载

结果完全不同——一个是聊天回复，一个是可以立刻打开的 Word 文件。

Skills 的核心价值总结

学完这一章，你需要记住以下三点：

  • 1、Skills 让智能体从会聊天变成会干活：没有 Skills，智能体只是个知识渊博的聊天机器人。有了 Skills，它成为能真正完成任务的执行者。

  • 2、Skills 是可复用的经验包：一旦有人把生成 Word 文档这件事的经验写进了 Skill，所有人、所有次调用，都能得到稳定一致的结果。不会因为换了个人提问就失效。

  • 3、Skills 是人与 AI 协作的桥梁
    人类把领域知识、流程经验、环境约束写进 Skill；AI 读懂后去执行。Skills 就是这座桥——人类专注定义怎么做，AI 负责真正去做。

概念 一句话总结
AI 智能体 能感知、推理、行动的 AI 系统，不只会聊天，还能执行任务
Skills 告诉智能体"如何完成某类任务"的说明书（Markdown 文件）
Skills 的价值 让任务执行变得准确、稳定、可复用

Skills 与 MCP 的区别

Skills 用于知识复用，MCP 用于能力扩展。

Skills

知识复用

  • 知识分享：经验、最佳实践、工作流程
  • 基于简单的 Markdown 文件，任何人都可以创建
  • 渐进式加载，Token 使用效率高
  • 无需服务器或后端设置
  • 适用于 Web / Desktop / CLI

MCP

能力扩展

  • 功能扩展：连接 API、数据库、外部工具
  • 需要编码能力和服务器端配置
  • 启动时加载全部工具定义
  • 对外部系统集成能力强
  • 更高的 Token 消耗与复杂度

技能的使用场景

Agent Skills 适用于各种场景，包括但不限于：

  • 领域专业知识：将法律审查、数据分析、代码规范等专业领域的知识封装成技能
  • 工作流程：将多步骤的任务流程固化为可重复的技能
  • 公司规范：将公司特定的代码规范、提交流程、文档模板等封装成技能
  • 工具集成：封装特定工具的使用方法和 API 调用

支持 Agent Skills 的工具

Agent Skills 是一个开放标准，被多种 AI 工具支持，包括：

  • Claude Code
  • OpenCode
  • GitHub Copilot
  • OpenAI Codex
  • 以及其他众多 AI 代理工具

这意味着你只需要编写一次技能，就可以在不同的工具中使用。
